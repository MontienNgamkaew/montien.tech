# สิทธิ์ครู Academix อัตโนมัติ

สมาชิกที่ยืนยันบัญชีแล้ว สถานะ active และมีตำแหน่ง **ข้าราชการครู / พนักงานราชการครู / ครูพิเศษสอน** ใช้ Academix สำหรับงานของตนเองได้อัตโนมัติ ไม่ต้องกำหนด app role ทีละคน รวมถึงสมาชิกเดิมที่ยังไม่มี app_roles ของ Academix

ผู้ที่ได้รับบทบาท `teacher` อย่างชัดเจนก็ยังเป็นครูตามสิทธิ์ที่ได้รับไว้ การมีตำแหน่งครูไม่เพิ่ม admin, approve, manage_users, manage_settings หรือสิทธิ์แต่งตั้งเจ้าหน้าที่

## งานที่เปิดให้ครู

- ส่งโครงการสอน (`course_syllabus`)
- ส่งแผนการสอน (`lesson_plan`)
- ส่งสื่อการสอน (`teaching_materials`)
- ดูผลและสถานะการส่งงานของตนเอง รวมการพิมพ์เอกสารส่วนตัวตาม workflow เดิม

**งานวิจัยพักไว้ตามคำสั่งผู้ใช้ ยังไม่มีการเพิ่มประเภทงาน ตาราง หรือหน้า research** และระบบ PNP Lesson Plan แยกต่างหากยังคงพักบริการ การส่งเอกสารแผนการสอนใน Academix ใช้งานได้ตามปกติ

## ขอบเขตและเงื่อนไข

สิทธิ์พื้นฐานครูคือ view/create/edit/export ของพื้นที่ **งานของฉัน** เท่านั้น ยังตรวจตัวตน เจ้าของรายวิชา/เอกสาร และ session ทุก request

- ต้องผ่านอนุมัติสมาชิกก่อนใช้งาน บัญชีรออนุมัติ ระงับ เก็บเข้าคลัง หรือยังต้องเปลี่ยนรหัสชั่วคราวไม่สามารถข้ามเงื่อนไขได้
- ใช้ภาคเรียนและรายวิชาของตนเองตามระบบเดิม
- สถานะเปิด/ปิดรับเอกสารและ deadline ของแต่ละประเภทใช้ค่าเดิม ส่งหลัง deadline ระบุ late ตามพฤติกรรมเดิม ไม่เปลี่ยนเป็นห้ามส่งโดยพลการ
- งาน pending ที่ส่งทับต้องยืนยันตามฟอร์มเดิม; งาน approved แก้ทับไม่ได้ตามเงื่อนไขเดิม
- ไม่ได้แก้โค้ดรับเอกสาร/อัปโหลด ถอนงาน หรือกติกาไฟล์เดิมในชุดปล่อยนี้ ข้อจำกัดการลบถาวรของรุ่น Portal V2 ยังคงเดิม
- ครูที่เป็น admin/staff อยู่แล้วคงสิทธิ์ดูแลที่ได้รับมอบหมาย และได้สิทธิ์ส่วนตัวพื้นฐานครูแยกกัน ไม่รวมสิทธิ์ส่วนตัวเข้าเพดานมอบหมายเจ้าหน้าที่
- ตำแหน่งครูอ้างอิงทะเบียนกลาง ผู้ใช้แก้ตำแหน่งตนเองผ่าน API profile ไม่ได้ การสมัครเลือกตำแหน่งครูยังต้องรอผู้ดูแลตรวจสอบและอนุมัติ

เมื่อเปลี่ยนตำแหน่งเป็นอย่างอื่น สิทธิ์อัตโนมัติตามตำแหน่งจะหายในการตรวจ request ถัดไป **แต่สิทธิ์ครูที่มอบหมายไว้อย่างชัดเจนยังคงอยู่** หากต้องการระงับบัญชีใช้สถานะบัญชีตามปกติ ไม่จำเป็นต้องลบประวัติ

## วิธีใช้

ครู login Portal ด้วยบัญชีเดิม แล้วเลือก Academix / งานของฉัน ถ้าค้างหน้าเก่าให้ refresh ผู้ดูแลไม่ต้องเพิ่มบทบาทครูทีละคนสำหรับสามกลุ่มตำแหน่งข้างต้น

หน้าผู้ดูแลและสิทธิ์แสดงป้าย **สิทธิ์ครูอัตโนมัติ** และขอบเขตเฉพาะงานตนเอง ป้องกันการตีความ scope ทั้งองค์กรเป็นสิทธิ์ดูงานผู้อื่น การกดบันทึกหน้าสิทธิ์ไม่แปลงบทบาทที่ได้อัตโนมัติให้เป็น role ถาวรโดยไม่ได้เลือก

## การพัฒนาและตรวจสอบ

ไฟล์เปลี่ยนจริง: `api/v2/core.php`, `api/v2/grants.php`, `portal-v2/assets/portal.js`, `portal-v2/index.html` ไม่มี schema ใหม่และไม่ backfill/UPDATE app_roles, role profiles, user ID, password hash, รายวิชา หรือเอกสารบน production

ทดสอบด้วยข้อมูลสังเคราะห์บน localhost **8 กลุ่มผ่าน**:

1. ทั้งสามตำแหน่งครูเข้าได้โดยไม่มี app role เดิม; ไม่ได้สิทธิ์ admin/approve/delegate
2. สมาชิกตำแหน่งอื่นไม่ได้สิทธิ์เพิ่มอัตโนมัติ
3. ครูที่สมัครใหม่ต้องรออนุมัติ
4. ส่งงานจริงใน fixture ครบสามประเภทและดูผลของตนเองได้
5. ปิดรับ, late และ approved-lock คงเงื่อนไขเดิม
6. เปลี่ยนตำแหน่งและระงับบัญชีมีผลกับสิทธิ์อัตโนมัติ
7. ยืนยันส่งทับ pending โดยรักษา submission ID และแก้งานคนอื่นไม่ได้
8. บันทึกหน้าสิทธิ์อัตโนมัติไม่สร้าง teacher role ถาวร

Regression หลายบทบาท **8 กลุ่มผ่าน** และระบบสมาชิก/SSO เดิม **7 กลุ่มผ่าน** ตรวจ Chrome fixture แล้ว ไม่มีการส่งงานจริงหรือสร้างบัญชีทดสอบจริงบน production
